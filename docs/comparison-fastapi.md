# fusionframe vs FastAPI

`fusionframe` is not trying to win by being a thinner API framework than FastAPI.

The intended value proposition is different:

- FastAPI is strongest as an API toolkit.
- `fusionframe` is aiming to be a batteries-included application framework.

## Where FastAPI is stronger today

- ecosystem maturity
- production adoption
- OpenAPI depth
- typing and dependency injection polish
- long-term stability guarantees

## Where fusionframe is trying to be better

- fewer moving parts for app-style backends
- sessions, auth, permissions, admin, templates, static files, GraphQL, jobs, and plugins built in
- full-stack backend ergonomics for small-to-medium products
- easier path from prototype to internal tool or SaaS admin backend

## Who should use fusionframe

Use `fusionframe` if you want:

- APIs and rendered pages in one framework
- auth, sessions, admin, jobs, and migrations without assembling many libraries
- an async Python framework with a monolith-friendly default path

Use FastAPI if you want:

- the most mature API-first framework experience
- deeper ecosystem support today
- maximum compatibility with existing FastAPI infrastructure

## Comparison summary

`fusionframe` should be judged as an integrated application framework, not as a pure FastAPI replacement.
